# Pose-to-mannequin spike

Findings are in `docs/pose-to-mannequin.md`. This is the code that produced them.

**Nothing here is wired into the SDK.** It drives `bin/cli eval` and the probe at
`src/vision/pose_landmarks.py` from the outside.

## Prerequisites

The `python-mediapipe/` venv (already present for faces) and the pose weights:

```bash
curl -o models/pose_landmarker_full.task https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_full/float16/1/pose_landmarker_full.task
```

## Running it

Each script is run from the project root with the mediapipe venv's interpreter.

```bash
./python-mediapipe/Scripts/python.exe tools/pose-spike/endtoend.py
```

| script | what it answers |
| :--- | :--- |
| `pose_rig.js` | the mapping alone, no detector — run it through `bin/cli eval` |
| `variants.py` | which rendering of a figure the detector sees, against a photo/sculpture/drawing control |
| `contrast.py` | contrast against anatomy: which variable is the gate |
| `endtoend.py` | render, detect, map, rebuild, and report the recovery error |
| `fetch_photos.py` | the three control images — **spends from the `Photo` budget** |
| `photo_chain.py <slug>` | one real image right through the chain, as a three-panel comparison |
| `find_illustrations.js` | resolve candidate drawn subjects — free, spends nothing |
| `illustrations.py` | the case that matters: does the detector see a **drawn** figure? |
| `comic_chain.py` | the same via `Assets.cutout` — **needs asset requisition configured**, which reports a budget of 0 in this CLI context |

The `Photo` budget is per session and each CLI run is its own session, so re-running a fetch
spends again rather than reusing the last run's allowance.

`pose_map.js` is generated by splitting `pose_rig.js` at its first section rule, so that the
analytic test and the end-to-end test share one implementation of the geometry rather than two
that could disagree. Edit `pose_rig.js` and re-split:

```bash
./python-mediapipe/Scripts/python.exe -c "import io; s=io.open('tools/pose-spike/pose_rig.js',encoding='utf-8').read(); io.open('tools/pose-spike/pose_map.js','w',encoding='utf-8').write(s[:s.index('// ---')])"
```

## Output

`analytic-overlay.png` and `detector-overlay.png` are the results worth looking at — truth in
graphite, recovery in red. **Neither is committed**: the repository ignores `*.png` wholesale, so
these are local artifacts like any other render. Re-run `pose_rig.js` and `endtoend.py` to
regenerate them, along with the per-case intermediates this folder's `.gitignore` covers.
